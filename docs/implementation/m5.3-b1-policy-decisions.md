# M5.3-B1 — Pure Policy Decision Engine

**Status:** Isolated deterministic component, not wired into CommandGateway.  
**Baseline:** AI Company OS core contract RC1. No runtime/tool access enabled.

## Scope

This change introduces a default-deny Python policy evaluator with three decisions: PERMIT, DENY, and APPROVAL_REQUIRED. The evaluator accepts a versioned immutable policy book and host-derived PolicyContext, ScopeGrant and (optionally) ApprovalSnapshot. It does **not** authenticate these dataclasses: untrusted caller-provided values could be forged. The future trusted gateway must resolve them from canonical records.

## Decision order

1. Reject unknown action, foreign principal/appointment/task/resource tenant.
2. Require active appointment, eligible role/capability, allowed company/task states.
3. Require an exact single-appointment grant binding task, action and resource; do not union permissions across roles.
4. Verify grant expiration and bounded budget. Evaluation does **not** reserve budget.
5. Reject self-review and controlled-subagent review when independence is required.
6. For L3 risk, require a time-bounded grant and an exact human approval with matching company, task, action, resource, payload SHA-256, record revision and policy version.
7. Explicit denied or revoked approval means hard DENY, not a request for additional approval.

A pure PERMIT is **not** proof of action completion, an execution lease, actual Owner authentication or one-time approval consumption. High-impact side effects remain disabled.

## Test evidence

Run locally (Python 3.11+, standard library):

    python -m unittest discover -s tests -p 'test_policy.py' -v
    python -m compileall -q company_os tests

**Observed 2026-11-08:** 49/49 new policy module tests passed in the isolated local environment. They cover unknown actions, tenant boundaries, role/capability/task checks, stale grants, negative budgets, exact resource scopes, self-review, L3 approval fingerprints, expiry, denied approvals and immutable policy books. The existing 71 gateway/workflow tests were **not rerun together with these 49**. Do not claim 120 combined passing tests. GitHub CI has not run.

## Non-goals / open security requirements

- No real host-authenticated principal or transport.
- PolicyContext, grants, approvals and role/capability snapshots are not persisted or cryptographically attested.
- PolicyEvaluator is not called by the current CommandGateway and cannot guard any real tool.
- Budget checking is not atomic reservation; approval validation does not consume approval.
- No authenticated human Owner approvals, evidence criteria enforcement, OperationAttempt, side-effect reconciliation or production readiness.
- Role examples in tests are fixtures, not a software-specific restriction on the company core.

## Next milestone: M5.3-B2

Build a **trusted SQLite policy snapshot resolver and gateway binding**. It must load current identity, appointment, task, company and capability facts from trusted state under the same transaction; create exact grants from versioned policy; enforce the policy outcome on every exposed command; audit denials; and add negative integration tests for foreign tenants, combined role switching, stale grants, revoked appointments and altered approval fingerprints.

No autonomous external action may be enabled until the authenticated host, one-time approval consumption, budget reservation, real acceptance verification and operation reconciliation gates are implemented and proven.
