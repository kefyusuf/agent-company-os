# M5.5 T-PR3 — Provider Selection and the Recorded GO (design)

**Status:** Design drafted and **decisions approved by the owner (2026-11-28)**; implementation (T-PR3b) not started. Nothing here enables a real external effect — the recorded GO in the ledger is the only instrument that can.  
**Base:** [M5.5 real transport review](m5.5-transport-review.md) decisions #1–#6; [T-PR1](m5.5-t-pr1-two-phase-dispatch.md) (G-T1/G-T2) and [T-PR2](m5.5-t-pr2-transport-seam.md) (G-T3/T4/T5/T6/T7/T9) merged — **7/10 gates evidenced**.  
**Gates targeted:** G-T8 (budget settlement for a real transport), G-T10 (independent transport review), DNS-rebinding/IP-pinning (deferred from T-PR2), and the **explicit owner GO**.

## Goal and non-goal

Close the last three M5.5 items and define — precisely, revocably, and in the ledger — what a recorded GO authorizes and what it never authorizes. This design performs **no real dispatch**: the adapter slice implementation that follows it still only executes against the loopback harness unless and until a live smoke test is separately approved.

## Provider candidates (read-only family, per M5.5 decision #4)

| Candidate | Surface | Account/credentials | Risk profile | Fit |
| --- | --- | --- | --- | --- |
| **A. Web fetch** — HTTP GET of fixed public URLs | One method (GET), text/metadata response | None (public URLs) or a static per-endpoint token | Smallest: read-only by construction, no third party beyond the target site | Highest: reuses `ExternalHttpTransport` almost verbatim |
| B. Web search API | Vendor SDK/HTTP API, query → results | Third-party account + API key | Vendor terms, key management, result content untrusted | Medium: needs vendor onboarding first |
| C. RSS/Atom feed fetch | XML GET + parse | None | Narrow but parser complexity (XML attack surface) | Low priority |

**Recommendation (owner Q1): A — web fetch of fixed public URLs.** It adds no third party, no account, no new credential class beyond what T-PR2 already handles, and the endpoint allowlist (G-T6) maps 1:1 to "the fixed public URLs the owner configured". Search/RSS remain future candidates behind their own review.

## G-T8 — budget settlement for a real transport (documentation gate)

Semantics are **unchanged and re-stated** for the real transport: reserve at authorization (phase 1); settle immediately from the HTTP response — refund on `failed`, consume on `succeeded`; hold on `unknown`; hold on terminal `unresolved` (human decision settles). The real transport introduces no new budget state; the only timing note is that `unknown` holds persist across process restarts and are settled by `operation.recover`/`operation.reconcile`/`operation.decide`, never by the transport itself. Recorded here; no code change.

## G-T10 — independent transport review

The repository's documented norm gap (owner self-review until a second reviewer exists) applies. Proposal (owner Q4): supplement the owner self-review with a **Mimosa deep security scan of the transport slice** (`company_os/transport.py` + the two-phase ledger paths), recorded as independent tool evidence in the PR body and SECURITY.md dispositions. A human second reviewer remains a standing recruitment item, not a blocker invented for this stage.

## DNS-rebinding / resolved-IP pinning (deferred from T-PR2)

For non-loopback endpoints, DNS rebinding is closed by **resolve-and-validate**: at request time the transport resolves the endpoint host, validates every resolved address against a deny-list (private, loopback, link-local, cloud-metadata ranges) **for non-loopback endpoints only** — the loopback harness exception (owner decision Q2, T-PR2) stays intact — and pins the connection to the validated address. A host that resolves into a denied range fails closed (`TRANSPORT_DNS_DENIED`) before any connection. Contract-testable with a resolver stub; no real DNS needed in CI.

## The GO mechanism (the core of this design)

A GO is a **ledger-recorded owner decision**, not a code flag. One GO authorizes exactly one narrow thing:

| GO scope | What it authorizes | What it never authorizes |
| --- | --- | --- |
| **Live smoke GO** (owner Q2) | One (or a small bounded set of) synthetic read-only dispatch(es) to a single fixed allowlisted public URL, executed manually by the owner, outside CI, with the full two-phase ledger + audit trail running | Routine operation, CI execution, autonomous dispatch, any write, any non-allowlisted target, any credential-bearing provider |
| Production GO (future, separate decision) | The selected provider family under the recorded constraints | Still never: writes, payments, customer-data export, autonomous redispatch |

GO properties: recorded in `docs/PROJECT_STATUS.md` with date, scope, target URL, expiry; **revocable at any moment** by the existing FLOW-04 machinery (company `paused`/`suspended` stops every dispatch at the gateway hard gate) — no new revocation code needed. Even under GO, every dispatch keeps: fresh authorization at phase 1, transport identity, budget reservation, audit trail, and the `unknown`→recovery path.

## Decisions (approved by the owner, 2026-11-28)

1. **Provider candidate (Q1):** **A — web fetch of fixed public URLs**, via the existing `ExternalHttpTransport`. Owner approved over search API (B) and RSS fetch (C).
2. **First GO scope (Q2):** **live smoke only** — a bounded, manual, outside-CI synthetic read-only call to a single fixed allowlisted public URL; production GO stays a separate future decision. Owner approved.
3. **IP-pinning approach (Q3):** **resolve-and-validate** — at request time the endpoint host is resolved and every resolved address is validated against a deny-list (private, loopback, link-local, cloud-metadata ranges) for non-loopback endpoints only; the connection pins to a validated address; a violation fails closed (`TRANSPORT_DNS_DENIED`) before any connection. The loopback harness exception (T-PR2 Q2) stays intact. Owner approved.
4. **G-T10 review form (Q4):** **Mimosa deep security scan of the transport slice** recorded as independent tool evidence + owner self-review with the documented norm-gap label; a human second reviewer remains a standing recruitment item. Owner approved.

## What stays NO-GO

Until the owner records an explicit GO in the ledger: no real dispatch of any kind. Even after a live smoke GO: no routine or autonomous operation, no writes, no payments, no customer-data export, no non-allowlisted targets, no CI-hosted external calls, no production deployment. The honest status vocabulary applies unchanged.
