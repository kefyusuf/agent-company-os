# M5.1 — Persistence Foundation (first implementation PR)

**Status:** Local implementation of a *strict subset* of the M4.3 contract.  
**Prerequisite:** M4.3 docs + M4.4 plan (PR #1, still awaiting merge).

## Implemented in this PR

- SQLite tables with company-scoped composite keys: `Company`, `Position`, `AgentIdentity`, `Appointment`, `Task`.
- Tenant-scoped parent and appointment references, a single CEO fixture root, and one active appointment per position.
- An **inactive** demo organization: CEO → CTO → Engineering Manager → Backend Engineer.
- Minimal `CreateTask` and `TransitionTask` commands with actor appointment checks.
- Planning-only transitions: `draft → ready → assigned`; cancellation allowed from draft/ready.
- Explicit rejection of unauthorized cross-appointment task assignment until Delegation is implemented.
- Optimistic Task revision checks; receipt-based idempotency with payload comparison.
- Canonical state + audit + command receipt committed in one local SQLite transaction.
- Reopen-the-database persistence check, duplicate command, denied actor and invalid-transition tests.

## Deliberately not implemented

The human Owner principal authentication, real Blueprint compilation, active company readiness, Department Finance coverage, Delegation, AgentRun, reporting/review, evidence verification, AI models, policy engine, approvals, lease/recovery, independent review, and any external side effects.

**Do not call these gaps “passed” or bypass them in the application.** In particular, the SQLite `Store` class is a local library with a trusted fixture actor, **not an authentication boundary**. Methods that would need new authorization rules must remain unavailable until they are implemented.

## Run locally

Requirements: Python **3.11+**. No pip install and no paid CI required.

```bash
python -m unittest discover -s tests -v
```

The tests create isolated temporary SQLite databases; they do not require credentials or change real company systems.
