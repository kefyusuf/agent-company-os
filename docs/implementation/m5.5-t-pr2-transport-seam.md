# M5.5 T-PR2 — Transport Seam Hardening and the Contract Harness (design)

**Status:** Design drafted and **decisions approved by the owner (2026-11-27)**; implementation not started. Nothing here enables a real external effect.  
**Base:** [M5.5 real transport review](m5.5-transport-review.md) decisions #1–#6 (2026-11-20); [T-PR1](m5.5-t-pr1-two-phase-dispatch.md) merged (PR #36) — G-T1/G-T2 evidence recorded.  
**Gates targeted:** G-T3 (zero credentials), G-T4 (idempotency mapping), G-T5 (failure mapping, no retry), G-T6 (allowlist + TLS), G-T7 (opaque evidence), G-T9 (audit coverage).

## Goal and non-goal

Harden the adapter seam so the first real provider inherits the boundary rules by construction, and add the **local fake-HTTP contract harness** that proves those rules over real HTTP — without any external network. The only HTTP endpoint that exists in this stage is a **localhost fake provider** inside the test suite; no production endpoint, provider or credential exists. NO-GO unchanged.

## The seam becomes a typed protocol

T-PR1 left `ScriptedExternalAdapter` as the only adapter, duck-typed. T-PR2 formalizes the seam as a `typing.Protocol` (`ExternalAdapter`) with the exact surface the ledger already uses:

```python
class ExternalAdapter(Protocol):
    def transport_key(self, attempt_id: str) -> str: ...
    def dispatch(self, attempt: dict) -> dict: ...
    def status(self, adapter_ref: str) -> dict | None: ...
    def status_for_transport(self, transport_key: str) -> dict | None: ...
```

`ScriptedExternalAdapter` and the new `ExternalHttpTransport` both satisfy it; `mypy` (active in CI) checks conformance. The ledger layer (`ExternalOperationManager`, gateway) stays adapter-agnostic — it never learns which adapter it holds.

## `ExternalHttpTransport` shape (fixture-grade, localhost-only in this stage)

- **Endpoint allowlist (G-T6, T6):** host-configured at construction; `dispatch` resolves the target endpoint from the attempt payload and denies non-allowlisted endpoints **before any network activity** (`TRANSPORT_ENDPOINT_NOT_ALLOWED`). The allowlist is transport-level config — it complements, never replaces, the policy grant (which still scopes who may dispatch which external resource).
- **TLS policy (G-T6):** `https://` required for every allowlisted endpoint **except loopback `http://127.0.0.1`/`http://localhost`**, the documented fixture exception that lets the contract harness run without certificates. Non-conforming scheme → `TRANSPORT_INSECURE_SCHEME` before any network activity.
- **Credential boundary (G-T3, T3):** the transport receives a **host-provided credential resolver** (callable `endpoint -> str | None`) at construction, out-of-band. Credentials never travel through command payloads, attempt rows, audit events, evidence refs or logs; the transport injects the credential into the request header internally and records only its **presence** in audit metadata. Invariant test scans attempt rows, audit events and adapter history for the secret value.
- **Idempotency mapping (G-T4, T4):** every dispatch sends the T-PR1 transport identity (`transport_key`, derived from `attempt_id`) as the `Idempotency-Key` header. The fake provider records the first outcome per key and replays it on duplicate keys — contract test proves the mapping. Provider-side dedup is what makes the phase-2 crash window safe to retry at the *provider* level without violating decision #2 (no dispatch retries at the transport layer; recovery still only re-queries status).
- **Failure mapping (G-T5, T2):** per M5.5 gate text, network-level failures (timeout, connection error, reset) and 5xx map to **`unknown`**; 429 maps to `unknown` (owner decision #3). **Definitive protocol rejections (4xx client errors other than 408/429) map to `failed`** — open question Q1 below. Nothing is ever auto-retried.
- **Opaque evidence (G-T7, T5):** the transport returns only `{outcome, adapter_ref, evidence_ref}` where `evidence_ref` is an opaque reference (request id). Raw response bodies are never returned by the seam and never persisted; the invariant test asserts nothing from the response body lands in the DB.
- **Status surfaces (G-T2 continuity):** `status(adapter_ref)` and `status_for_transport(transport_key)` query the provider's status endpoint; a provider that has not settled returns `unknown`.

## Contract harness (owner decision #5)

`tests/test_transport.py` runs a **localhost fake provider** on the stdlib `http.server` in a thread — real HTTP over the loopback interface, zero external network, zero CI minutes risk. Scenarios: idempotency header present + duplicate-key replay; 5xx → `unknown` then later settled status → recovery resolves; timeout → `unknown`; 4xx → `failed` (per Q1); non-allowlisted endpoint denied pre-network; insecure scheme denied; zero-credential scan (G-T3); opaque-evidence scan (G-T7); audit coverage for dispatch/unknown/failed (G-T9). An optional live smoke test against a real endpoint stays **deferred** until the owner records an explicit approval outside CI.

## Decisions (approved by the owner, 2026-11-27)

1. **4xx mapping (Q1):** definitive client-error rejections (400/401/403/404) map to **`failed`**; 408/429, 5xx and all network-level failures map to **`unknown`**. Owner approved over the all-unknown mapping: a definitive refusal is not ambiguity, and mapping it to `unknown` would strand budget on failures that provably did not happen.
2. **TLS exception scope (Q2):** `https` required everywhere except loopback `http://127.0.0.1`/`http://localhost` for the contract harness — a documented, checkable fixture exception; CI never talks to a non-loopback host. Owner approved over certificate infrastructure for the harness.
3. **Credential resolver shape (Q3):** host-provided callable at transport construction (`endpoint -> str | None`), out-of-band; a missing credential for an allowlisted endpoint is denied **before** the call (`TRANSPORT_CREDENTIAL_UNAVAILABLE`) — never a silent unauthenticated dispatch. Owner approved over allow-anonymous fallback.
4. **Allowlist ownership (Q4):** transport-level, host-configured list of exact endpoint origins; policy grants continue to scope who/what at the ledger layer — two orthogonal, fail-closed boundaries. Owner approved over a DB policy table.

## What stays NO-GO

No real provider, no non-loopback network traffic, no credentials in code or fixtures (the harness credential is a synthetic test value), no production endpoint, no exactly-once claims, no autonomous redispatch, no unattended recovery, no payments, no customer-data export. Production deployment remains NO-GO until every gate has evidence and the owner records an explicit GO.
