# M5.5 — Real Transport Review (pre-provider gate)

**Status:** Design drafted and **decisions approved by the owner (2026-11-20)**; implementation not started. Nothing here enables a real external effect.  
**Contract base:** M4.3 `ai-company-os.core@0.1.0-rc1`; M5.4 external operation boundary (D-PR1/2/3, PRs #20/#23/#27) merged and fixture-complete.  
**Master-spec anchor:** PR-C "runtime/tool adapter" — this document defines the review gate that PR-C must pass before the first real adapter exists.

## Goal and non-goal

Define, **before any real provider integration is written**, the review gate the transport slice must pass: the threat-model delta of leaving the process, the concrete gate checklist, and the owner decisions that turn each hazard into a recorded rule. The goal is that the first real adapter inherits safe semantics **by construction** — the same reason the OperationAttempt ledger existed before any real dispatch.

This document does **NOT** implement a provider, touch network code, or relax any NO-GO. Real providers, credentials in code, network I/O, exactly-once claims and autonomous redispatch remain forbidden until the gates below pass **and** the owner records an explicit GO.

## Why now

The M5.4 design named exactly one remaining blocker for any real runtime: *"ExecuteExternalAction remains a NO-GO for production until this whole stage is merged AND a real transport review happens."* The stage is now merged; the ledger, state machine, reconciliation and human decision records exist and are CI-verified. Drafting the review before writing any transport code prevents the known failure mode it exists to prevent: handling `unknown` ad hoc at integration time.

## Threat model delta: in-process fixture → real transport

The fixture runs `adapter.dispatch()` inside the caller's SQLite transaction (INV-019 atomicity). A real transport breaks every assumption behind that:

| # | Hazard | Fixture assumption broken | Required direction |
| --- | --- | --- | --- |
| T1 | **Commit/dispatch crash window** | Dispatch is in-transaction; a crash rolls everything back | Commit-then-dispatch: the attempt can rest in `authorized`/`dispatched` across process restarts; a recovery path must resolve orphans via adapter status — never by re-dispatching (FIX-10) |
| T2 | **Network ambiguity** | Outcome is scripted and total | Timeout, connection reset, 5xx are **`unknown`**, never inferred success/failure; no automatic dispatch retry |
| T3 | **Credentials** | No credentials exist | Secrets live in a host-side store, out-of-band; the adapter seam already receives no credentials — the transport must not smuggle them through payloads, attempt rows, audit events or logs |
| T4 | **Duplicate effects** | One adapter call per attempt | Exactly-once is not claimable over networks; provider-side idempotency keys (mapped from `attempt_id`) are mandatory for non-idempotent actions |
| T5 | **Evidence integrity** | Evidence is an opaque fake string | Provider evidence stays an opaque reference; raw response payloads are never persisted (digests/refs only) — the audit payload rule already in force |
| T6 | **Egress control** | No network exists | Provider/endpoint allowlist per company policy; TLS enforced; no arbitrary URL fetch through the adapter seam |
| T7 | **Rate limits / quota** | No external capacity | Provider 429s have a recorded mapping (owner decision below); company budget pool stays the primary spend gate |
| T8 | **Transport auth** | In-process identity | Credential handling, rotation and least-scope tokens documented per provider; no shared long-lived credentials in fixtures |
| T9 | **Process boundary** | Trusted host is in-process | Sessions stay opaque, unserializable objects; moving the host out-of-process later is a separate review, never a payload change |
| T10 | **Audit completeness** | Fake outcomes audit trivially | Real dispatch, status query, timeout and failure each audit with timing + correlation id, without secrets or raw payloads |

## Gate checklist (each gate needs recorded evidence before a real adapter ships)

| Gate | Requirement | Evidence form |
| --- | --- | --- |
| G-T1 | Commit-then-dispatch semantics designed; attempt states may rest at `authorized` across restarts | Design record in this doc series + state-machine extension note |
| G-T2 | Crash recovery resolves orphaned `authorized`/`dispatched` attempts via adapter status, fail-closed | Recovery command + tests proving no blind redispatch |
| G-T3 | Zero credentials in DB rows, audit events, logs or test fixtures | Invariant test + grep-style scan evidence per PR |
| G-T4 | Provider idempotency mapping (`attempt_id` → provider key) recorded for non-idempotent actions | Transport design section + contract test |
| G-T5 | All transport failures map to `unknown`; dispatch is never auto-retried; redispatch only via D-PR3 reissue or a fresh attempt with new authorization | Contract tests incl. timeout/cancelled-request cases |
| G-T6 | Endpoint allowlist + TLS enforced at the seam; arbitrary URLs denied | Deny-code test + config review |
| G-T7 | Evidence stored as opaque refs; raw payloads never persisted | Invariant test |
| G-T8 | Budget settlement timing for real transport documented (hold on `unknown`, refund on settled `failed`, hold on terminal `unresolved` — unchanged) | Ledger note; no new budget semantics without owner review |
| G-T9 | Audit coverage for dispatch/status/timeout/failure | Audit assertions in contract tests |
| G-T10 | Independent review of the transport slice before the first real dispatch | Review record; owner self-review only with the documented norm-gap label |

## Decisions (approved by the owner, 2026-11-20)

1. **Recovery authority (T1/T2):** an explicit trusted-host recovery command, role-gated and audited, that resolves orphaned attempts **only** from adapter status evidence (same discipline as `operation.reconcile`); no automatic background recovery. Owner approved over the supervisor-process alternative.
2. **Transport-level retry policy (T2):** status queries may retry idempotently (read-only, budget-neutral); **dispatch retries are forbidden** at every layer — the only redispatch paths are D-PR3 reissue (human-gated) or a brand-new attempt with fresh authorization. Owner approved; codifies FIX-10 at the transport layer (G-T5).
3. **429 / rate-limit mapping (T7):** map to **`unknown`** — the outcome is genuinely undetermined, and mapping to `failed` would refund a budget hold for an effect that may still land. Owner approved over the `failed` mapping.
4. **First real provider scope (T6):** after the gates pass, the first candidate is a **read-only** provider family (e.g. web fetch/search), never payments, writes, or customer-data export. Owner approved; the actual provider choice remains a separate owner decision at GO time.
5. **Test strategy (all gates):** contract tests run against a **local fake HTTP server** — no real network in CI; an optional live smoke test exists only behind an explicit, recorded owner approval, outside CI. Accepted as drafted (owner reviewed in conversation, 2026-11-20).
6. **Milestone numbering:** this gate is recorded as **M5.5** (accepted as drafted, 2026-11-20). Renumbering would not change content.

## What stays NO-GO

Real providers, network I/O, credentials in code or fixtures, exactly-once claims, autonomous redispatch, unattended background recovery, payments, customer-data export and production deployment remain forbidden until every gate above has recorded evidence **and** the owner has recorded an explicit GO in the project ledger. The honest status vocabulary applies unchanged.
